# 修改牛顿分解复用：公平 quick8 四臂结果（2026-08-28）

## 结论先行

在 8 个真实扫描步、每步强制力学的 solver-stress 窗口中，lagged tangent + PARDISO phase-33 **确实减少了力学数值分解，但净加速有限**：

- CPU 装配 + CPU PARDISO：四轮 AB/BA 的配对中位加速 **1.054x**，约减少 5.1% 墙钟；
- GPU 装配 + CPU PARDISO：配对中位加速 **1.020x**，约减少 1.9% 墙钟；
- 力学切线构造和力学数值分解都从 16 次降到 12 次（-25%），但力学线性求解从 16 次增到 23 次（+43.8%），其中 11 次是 phase-33 回代；
- 四条 arm 均 4/4 通过身份、profile、步数、ledger、健康和末帧字段 gate，modified 的 CPU/GPU 四次配对均快于同平台 full；
- 末帧温度相同，位移、应力和等效塑性应变差异很小，详见下表。

因此，**分解复用值得进入完整合同的 CPU 候选验证，但不应预期数量级加速；GPU 端约 2% 的短窗收益不足以设为默认。** 本记录不是完整 639 步性能结论，也不是物理验证。

## 为什么这次是公平消融

审查发现初始 [`QUICK8-20260828.md`](QUICK8-20260828.md) 的 full arm 没启用 mechanics residual-only，而 modified 路径自动使用真实残量检查，导致原 1.164x/1.023x 混入了“省最终无用切线”的收益。该旧结果已撤回为混杂试跑。

本组修正为：

1. 四个 arm 都启用 `--mechanics-residual-only-check`，只让 modified arm 增加 `reuse=2, refresh_ratio=0.9`；
2. 1 次 warmup 后做 4 次计时，奇数轮正序、偶数轮逆序；speedup 用每轮 full/modified 配对比值的中位数；
3. GPU residual/assembly 计时在停止计时前执行 `block_until_ready()`；
4. PARDISO 统计按 thermal/mechanics nonlinear solve 做快照差，本表只用 mechanics 分项确认 phase-33；
5. `experiment_manifest.json` 绑定输入、合同、线程、arm、环境、Git HEAD 和运行时代码树；任一重复不健康或缺证据时比较器不给 speedup。
